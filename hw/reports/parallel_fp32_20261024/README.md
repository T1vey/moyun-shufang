# 七轴 FP32 并行逆解与软件提速交付记录

本记录对应 2026-10-24 的 `ZYNQArm` 修改。**软件联合回归、HLS 综合、RTL 协同仿真和完整 Vivado 平台编译均已通过。100 MHz 实际约束下布局布线时序收敛，bit/hwh/xsa 已生成并完成哈希核对。尚未把本次版本部署到 ZYNQ 或连接机械臂验收。**

工程根目录旧 `README.md` 中的 2026-10-18 板端速度、旧发布目录、逐字节一致等结论属于历史版本，不是本次 FP32 版本的验收证据。

## 1. 本次分工与源码

| 环节 | 当前实现 |
|---|---|
| 手机上传、云端生成线稿、GUI、笔画提取与时间规划 | ZYNQ PS 上的应用代码 |
| 连续七轴逆解 | PL 内三级 DATAFLOW：几何分解 → CORDIC 与连续选解 → 按顺序写出 |
| 主机与 PL 通信 | 三个 M_AXI 接口：`gmem_control` 读配置及实时取消；`gmem_input` 读目标；`gmem_output` 写关节与完成头 |
| DDR 通道 | 控制、目标读取经 HP1；结果写入经 HP3；LCD 保留 HP0，已有 vision 核保留 HP2 |
| 显示、触摸、第二网口 | 保留完整平台的 MD0700R、GT911、GE_PL |
| 线条细化 thinning | 本次完整平台没有对应 lineart IP，软件直接选 CPU；不关闭其他已存在的 PL 模块 |
| 机械臂命令 | 保留既有 SDK/控制器接口、连续队列、GUI 速度与停止处理 |

核心源码位于 [`hls_source/tcb705_parallel_fp32`](../../../hls_source/tcb705_parallel_fp32/README.md)。几何、乘除、选解使用单精度；反正切内部为定点 CORDIC，输入输出是 FP32。最终版本复用一个 CORDIC 通道计算七个角，三级任务仍通过 FIFO 并行运行。

DDR 缓冲区沿用现有 FP64 打包布局，在边界转换为 FP32/从 FP32 扩展回去。因此这是**计算单精度化，不是全部传输数据宽度减半**。新核只支持 `IK_CHAIN`；`FK_ROWS` 明确拒绝，普通 CPU FK 仍可供现场状态、碰撞计算和离线分析使用。

模型不符合解析结构、接近奇异区域、分支不连续或超限时，PL 返回成功前缀及首个失败点，由 PS 处理剩余目标；这些目标的耗时不能按正常 PL 点吞吐量估计。

## 3. 单精度精度边界

测试保留独立 FP64 矩阵正解作为离线参考，不在运行时执行这套复核。

| 352 个控制器模型目标的离线检查 | 结果 |
|---|---:|
| FP32 离线预算：位置 ≤ `1e-5 m`（0.01 mm）、姿态 ≤ `1e-4 rad` | 352/352 |
| 原严格预算：位置 ≤ `1e-7 m`、姿态 ≤ `1e-6 rad` | 232/352 |
| 该组目标最大计算位置误差 | `2.36132e-7 m`（约 0.000236 mm） |
| 该组目标最大计算姿态误差 | `9.26272e-7 rad` |

另对 1,050,000 组反正切输入进行验证：1,041,041 组有效结果与原三通道算法逐位一致，8,959 组无效输入按合同拒绝，无失败。它验证的是该 CORDIC 改动，不代替整条机械臂轨迹精度验证。

单精度结果**并非全部满足旧双精度门限**。以上误差是模型计算误差，不包括标定、工具长度、舵机跟随、机械间隙、纸面与毛笔变形；不能将它写成真实笔尖精度保证。

完整历史轨迹另外做了连续离线回放，证据为 [`full_trajectory/summary.json`](full_trajectory/summary.json) 和 [`回放说明`](full_trajectory/README.md)：初始节点作为种子，后续 **21,679 个目标分 339 批**处理，每批使用上批最后一个已接受关节解，未重新使用历史种子重置分支。

| 完整轨迹离线回放 | 结果 |
|---|---:|
| 接受 / CPU 回退 / 未解决目标 | 21,679 / 0 / 0 |
| 拒绝批次 | 0 |
| 满足 FP32 离线预算 | 21,679/21,679 |
| 满足旧严格预算 | 12,838/21,679 |
| 最大计算位置误差 | `3.938234e-7 m` |
| 最大计算姿态误差 | `1.101510e-6 rad` |
| 相邻节点最大单关节变化 | `0.002955437 rad` |
| 与历史冗余关节解的最大单关节差值 | `0.263922 rad`，约 15.12° |

七轴冗余允许同一个笔尖目标对应不同关节姿态。本次输出沿连续分支变化，没有该样例中的跳解，但**不与旧版每个关节角逐点相同**。目标位姿计算误差小，也不能说明整只机械臂姿态完全重现历史动作。所有历史运动阶段都保留；该单条轨迹没有回退不代表任意纸面或奇异附近都不回退。这是同源 HLS C++ 核在电脑上的离线审计，既不是 21,679 点 RTL 计时，也不是板端/机械臂实测。

运行时没有测得的误差采用明确的“未评估”语义：新能力位 `capabilities=3`；成功输出的二进制误差字段为规范 quiet-NaN，PS 转为 Python `None`/JSON `null`。失败行的零占位也不会被解释为已测得零误差，CLI 显示“未评估”。

## 4. 软件实际改了什么

### 图案预览

- 直接使用前一步云端**返回的线稿图片**，不用手机原照片替代；本地线稿路径则显示本地原线稿。
- 图案计划不再生成机械臂轨迹预测 SVG。预览图片每任务编码一次并缓存；普通 PNG/JPEG/WebP 保留原字节，大图仅为屏幕显示限制到 384 KiB 以内，提取所用原图不变。
- 保留现有 GUI 风格、准备完成状态及原有确认/执行流程。手机上传仍在板端确认；原本本地“一键画画”的入口行为不因预览修改而改变。
- 书法、字库与手写保留预设笔画/用户笔迹预览，不依赖云端图片。

### 缺少 lineart IP 时的 CPU 路径

`lineart_backend.capability()` 检查平台 manifest、当前启动回执及 HWH/寄存器元数据。不存在对应能力是正常 CPU 配置：不尝试附着 Overlay、不申请 PL 租约、不通过每张图抛异常来发现缺失模块。

缺失结果缓存；启动、发布或相关元数据变更会使缓存失效。缓存命中时仅做文件状态检查。若后续平台确实加入 lineart IP，真正附着硬件时仍保留原有密封文件哈希校验；该正向路径仍有校验开销，本轮没有上板测量其毫秒数。

### 删除重复几何复核，保留执行所需数据

已移除 PL 候选的独立 FK 残差检查、PS 对 PL 结果再次 FK 检查、节点间曲线探针检查，以及按时间展开后再做的密集 FK 检查。真实执行准备中的 FK 合并检查、关节段插值误差复核和手写中间点 FK 复核也不再走生产流程。

保留实际执行需要的时间戳、插补系数、SDK 时间采样帧，以及有限值、关节限位、步长、速度/加速度/加加速度约束、原节点碰撞、取消/停止、现场反馈和超时处理。**删除的是额外几何正确性复核，不是删除执行时间轨迹。**

取消这些复核后，软件不再承诺运行时逐段证明笔尖路径误差或垂直姿态误差满足旧阈值；离线测试仍可对选定轨迹独立评估。

### 命令数量可能影响真实书写速度

执行准备改为保留全部已规划细节点，避免在没有 FK 验证的情况下继续使用旧合并结果。本机一个 40 mm 横笔画对照：558 个节点，旧版合并为 **78 条命令**，新版保留 **557 条命令**；准备计算约由 **100.6 ms 降至 3.7 ms**。

这只说明该样例的本机准备计算更短。命令增加约 7.1 倍，可能增加 SDK/控制器队列负担并影响实际动作速度。现有连续队列、GUI 速度和平滑设置保留，没有新增逐段 `sleep`；**尚不能据此宣布真实画画或写字更快**。后续需用同一纸面、速度、轨迹测量开始延迟、队列是否断流和完成总时间。
