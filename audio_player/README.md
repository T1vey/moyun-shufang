# 诗文朗读（2026-10-27）

本模块由屏幕服务拥有，播放本地 WAV，不调用云端，不驱动机械臂。首页「诗文朗读」包含 40 首绝句和 7 部名帖全文；支持逐句高亮、暂停、继续、停止、音量以及扬声器／PHONE 切换。界面沿用当前墨韵书坊的纸色、墨色、朱印和字体，适配 1024×600。

## 运行关系

`48 kHz WAV → ARM 后台线程（按实际芯片采样率分块适配）→ AXI-Lite FIFO → PL I2S → 音频芯片 → 扬声器 / PHONE`

- 源文件为 48 kHz、16 位、单声道；PL 同一采样送到左右声道。
- PL 的 16,384 点 FIFO 约容纳 341 ms；软件预填约 250 ms，每 40 ms 补充。
- PL 100 MHz / 8 提供 12.5 MHz MCLK。当前实机在 0x10 应答，对应 ES8388：主模式 /256 得到 48,828.125 Hz、3.125 MHz BCLK（每声道 32 位槽，前 16 位有效）。WM8960 分支保留其 PLL 48 kHz 配置。
- IP `audio_out_0`，AXI 地址 `0x40060000`，64 KiB；ID `0x41554431`，版本 `0x20261027`。
- 启动先验证平台清单、文件哈希及本次开机凭据，才映射 AXI。旧平台不访问新增地址；朗读入口仍显示，可浏览诗文，声音未就绪时禁止播放并提供重试。
- HTTP 和运动线程只入队。WAV 读取、校验、codec I²C、FIFO 填充及线程等待均在音频后台执行。伴读故障不会阻止机械臂停止。

## 伴读的含义

诗词／名帖选择页可勾选「边写边读」，默认关闭。开始执行已规划动作时开始朗读；停止、执行完成或异常退出时停止该任务拥有的伴读。不会停止用户之后手动开启的其他音频。

这是整篇伴读，不是逐字、逐笔同步。诗词换纸后新一页再次从该诗开始；录音先结束时不自动循环，书写先结束时朗读随之停止。

## 音频与出处

- `data/audio/manifest.json` 保存每篇标题、作者、出处、SHA-256、时长、分句起止及实测响度。
- `data/audio/texts/` 是可编辑释文；WAV 全部采用 Microsoft Huihui Desktop 合成，未经过人工校音，多音字和古文读音仍需试听。
- 绝句沿用项目原诗词库。祭侄文稿、寒食帖、蜀素帖取自台北故宫馆藏释文；张翰帖来自故宫博物院；兰亭序、千字文、前赤壁赋采用维基文库公有领域正文。
- 蜀素帖八首由保存的馆藏网页提取，未凭记忆补写。简繁转换、去除涂改说明和异文处理记录在 `tools/build_audio_texts.py`；每篇 JSON 保留来源 URL、来源哈希和说明。
- 47 段音频合计约 28 分 10 秒、154.76 MiB。最终文件实测平均 -17.20 LUFS，范围 -17.90～-16.37 LUFS；最大真峰值 -1.55 dBTP，全部低于 -1 dB。为留出重采样余量，归一化目标真峰值设为 -2 dB。
- 音量 100 对应 codec 输出增益不超过 0 dB；实际扬声器功率还取决于供电、负载和信号，不能由软件音量数字推定。

## 重新构建

1. PC 用项目 `.venv` 运行 `tools/build_audio_texts.py`；需要 `opencc-python-reimplemented`，来源缓存位于 `build/tcb705/audio_20261027/sources`。
2. 在能访问 Windows 已安装语音的 PowerShell 里直接执行 `tools/build_audio_sapi.ps1`，指定 TextDirectory、OutputDirectory 和 Microsoft Huihui Desktop。此机器通过 Python 子进程启动 SAPI 不可靠，应直接运行 PowerShell 脚本。
3. 运行 `tools/build_audio_wavs.py --skip-sapi --ffmpeg <FFmpeg 路径>`。工具按句拼接、保留首尾各 0.3 秒、两遍响度处理，再测量最终 48 kHz 文件，生成新清单。
4. 板端无需 SAPI、FFmpeg 或 OpenCC，只需工程原有 numpy。

FPGA 工程由 `scripts/build_audio_fp32.ps1` 创建并编译。默认工程为 `C:\fpga_build\audio_fp32_20261027\tcb705_parallel_fp32.xpr`；重新构建请指定一个新目录。脚本沿用 2026-10-24 的 FP32 HLS IP，不使用旧 76.923 MHz 规划核。旧 `hw/audio/create_audio_platform.tcl` 已禁用，防止覆盖升级后的规划平台。

已封装产物在 `overlay/tcb705_audio_fp32_20261027/`；完整 `.bit/.hwh/.xsa/.dcp` 位于上述工程的 `export/`。时序与资源报告保存在 `hw/reports/audio_fp32_20261027/`。

- XSim：400 组采样双声道校验，包含 I²C ACK/NACK、FIFO 清空、欠载静音和计数，TB_PASS。
- 完整布局布线：setup +0.265 ns、hold +0.050 ns、DRC 0 错误。

## 2026-10-27 SDA 修复

首版音频平台虽然时序通过，但实机帧计数始终为 0。对实际导出的 OOC 网表、routed DCP 和 DRC 报告核查后发现：模块内部推断的 SDA 三态被综合为常 0 输出，外部芯片应答没有读入。RPBF-3 和 HPDR-1 原本仅为 Warning，不能据此把“没有 DRC Error”当作音频接口已经正确。

修复采用显式 Xilinx IOBUF；布局布线后必须确认 SDA 同时具有真实输入和可释放的三态输出缓冲，否则不允许封装。新增寄存器：STATUS bit19=SDA、bit20=BUS_STUCK；0x24=I2C 完成计数；0x28=能力位（3）。I2C 命令 bit24=1 时仅发送地址和 STOP，不写芯片寄存器。

驱动先验证空闲 SDA 高，再用不存在的 0x22 地址做阴性对照，并探测 0x10、0x11、0x1A；每次事务必须看到完成计数变化。发现 ES8388 地址时明确报出型号分支，不能向其发送 WM8960 初始化表。0x1A 应答本身也不是芯片型号的完整身份证明，后续还需验证音频时钟。

WM8960 的 PLL K 高字节修正为完整 8 位，防止 0xDD4413 被截断为 0x1D4413。该实现与 Infineon 的 [WM8960 驱动](https://github.com/Infineon/audio-codec-wm8960/blob/master/mtb_wm8960.c) 一致。

修改版须经过 XSim、完整编译、板端冷启动和实际试听后才能宣称声音恢复；保留原平台及部署备份用于回退。

修复版已经完成 XSim 和完整编译：setup 0.136 ns、hold 0.011 ns，最终 pad 检查确认为 IBUF＋OBUFT。13 文件修复包已安装，43 项板端回归通过，等待重启加载后核对实际地址、约 48 kHz 帧率和播放声音。产物在 `overlay/tcb705_audio_iobuf_20261027/`，Vivado 工程在 `C:\fpga_build\audio_iobuf_20261027/`，报告在 `hw/reports/audio_iobuf_20261027/`。

服务公开 `init_attempt/phase/init_elapsed_s`，避免把上次失败快照误认为当前初始化进度。播放中硬件计数由后台每秒最多更新一次；HTTP 仅取缓存。`hardware_error` 与播放错误分开，计数读取失败不会阻止机械臂的停止或其他功能。

## 实机 ES8388 分支

IOBUF 修复后，实测地址探测为 0x22/0x11/0x1A 不应答、0x10 应答。ES8388 使用 8 位寄存器＋8 位数据，不能发送 WM8960 的 7＋9 位编码。`codec_es8388.py` 按原厂例程和手册配置参考电压、DAC、电源、16 位 I²S 主模式及输出混音。PHONE 对应 LOUT1/ROUT1；板载 MD8002A 扬声器输入来自 LOUT2/ROUT2。0% 关闭对应输出缓冲，PGA 不超过 0 dB，保留 −5 dB 数字衰减。

ES8388 没有 WM8960 那种可编程 PLL；为继续使用已验证的 FPGA，播放时将源 48 kHz 语音按 3125/3072 的比例分块适配到 48,828.125 Hz。原 WAV、哈希和分句时间轴不变；每次最多生成 12,000 样本，没有整篇额外副本。暂停／恢复和部分 FIFO 写入均使用绝对输出帧索引，进度仍以真实秒计。当前线性插值适用于语音的小比例采样率校正，并非通用带限音乐重采样器。

清单 `audio.sample_rate=48000` 指源文件格式；实际输出率由 `hardware.native_sample_rate_hz` 报告，实测值为 `hardware.frame_rate_hz`。不能把 ES8388 的实际输出标称成精确 48 kHz。

64fs 专用 XSim 验证通过：左右各 400 个样本一致，15,152 次空位补零检查为零错误。7 文件 ES8388 软件修复包已安装，62 项板端测试通过；备份在 `/home/xilinx/styles_check/audio_fp32_20261027/es8388_fix/`。无需再次加载 FPGA，仅重启 `tcb705-ui` 后进行真实时钟与声音验收。
