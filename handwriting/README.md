# 手写跟随模式（2026-10-23）

在糖画坊主界面“书法模式”旁新增“手写模式”，采用已选定的 A 方案深棕、金色、朱红界面。手写识别和轨迹规划全部在 ZYNQ ARM CPU 上运行。保持当前 FPGA 显示、触摸、GE_PL 和线稿提取平台；本次没有重新生成或烧录比特流。

## 操作流程

1. 点击“手写模式”：自动连接控制器，检查七轴、纸面、毛笔与归位配置，进入自动模式并按已有归位流程准备。此操作可能使机械臂运动。
2. 在字框内写一笔并抬手：立即提交当前这一笔，系统自动选择最近笔画，映射位置和尺寸，进行 CPU 连续逆解与下发路径检查，然后执行。无需确认识别结果。
3. 写完一笔后竖直抬笔悬停，保留 SDK 连接及执行线程。没有逐笔重新连接、使能、归位。
4. 机械臂未完成上一笔时，可以继续输入；后续笔画提前规划，按输入顺序执行。最多 8 笔未完成、每字最多 64 笔。队列满时界面拒绝新笔，避免无限积压。
5. “下一个字”停止接收当前字的新笔，等待已接收笔画执行完毕，再归位；成功后清空屏幕。字号 40～100 mm，已开始的字调整字号在下一字生效。此按钮不自动更换纸张或排版至其他纸面区域。
6. 速度使用主界面的同一个全局速度。停止会取消未执行笔画，保留屏幕笔迹，不自动续写；返回在停止请求受理后切换界面，后台仍等停止确认后才释放机械臂占用。

## 双模板与位置映射

- `templates.py`：35 类简化识别中心线，各带小幅扰动候选；用于识别，不含顿笔与下压细节。
- `recognizer.py`：64 点弧长重采样，保留方向、长宽比，特征粗排后对 5 个不同类别做 DTW。`native/handwriting_match.cpp` 在 ARM32 上编译为 CPU 动态库。匹配分数不是识别概率。
- `calligraphy/library.py`：复用已有执行模块的入笔、转折、收笔和压力曲线；不会把手指的抖动原样发给机械臂。
- `placement.py`：所有笔共享同一个字框坐标，映射到已标定纸面中心的字号正方形。横竖的窄轴保留执行模板的笔锋形状；不会把整笔缩放成填满字框。越界的笔锋轨迹拒绝执行。

## 常驻会话与连续性

`session.py` 用一个规划线程和一个机械臂所有者线程，HTTP 请求只入队。整段会话独占原有任务锁，避免与书法、图案、标定任务同时控制机械臂。每笔从上一笔预计的结束关节角连续逆解；执行前比较实际姿态，不一致则使所有后续计划失效，从实测关节角重新衔接。持续不稳定会报错，不跳过检查。

会话、字编号、笔画编号和内容摘要共同去重。网络响应丢失时不重发运动请求。规划结果绑定配置与路径摘要；停止、切字、会话退出会使旧结果失效。页面刷新恢复笔迹但不重新准备；心跳超过 8 秒停止，包含正在执行中的笔画。界面返回不依赖停止完成；机械臂锁仍需确认清队列且位置稳定，并满足 SDK 停止反馈或控制器伺服关闭后才释放。未释放期间，其他模式只能查看，不能开始新任务。

### r2 兼容修复

2026-10-23 实测板载 WebKitGTK 的 `PointerEvent` 和 `setPointerCapture` 均不存在，GT911 通过 X11 发送鼠标事件。页面现采用 Pointer Events 优先、Mouse/Touch Events 回退；修复旧 WebKit 不支持 CSS `inset` 的定位。输入取消不会提交半笔，触摸后的兼容鼠标事件不会重复提交。

SDK 连接建立后等待首组有效七轴反馈，再登录 Web 接口、读取最新状态和位置、按需使能；确认伺服与自动模式后设置统一速度并归位，顺序与原有绘画执行流程一致。准备阶段、原始异常、停止失败原因分别保留，避免被“正在停止”覆盖。已知只读变量/报警查询遇 HTTP 401 时重新登录并重读一次；使能或运动请求不重放。停止清队列可在重新登录后再次确认。

现场曾捕获 `ENABLE` 阶段 HTTP 401；只读对照中 SDK CONNECT 和设置原有速度均未使旧凭据稳定复现失效，因此不把原因直接归结为 SDK 踢掉登录。修复后错误包含 GET/POST 与接口路径，分别标记使能请求和使能等待阶段，便于后续现场判断。

`scripts/check_handwriting_webkit.py` 在板载 WebKit、独立 Xvfb 与本机假 API 上验证原生 X11 划动即时出墨、触摸提交、故障导航；不导入机械臂模块。`scripts/check_handwriting_ui.cjs` 以显式模拟后端验证识别、CPU 规划与执行队列，可设置 `HANDWRITING_LEGACY_INPUT=1` 验证鼠标回退路径。

## 实际执行接口与边界

`planner.py` 直接调用 CPU 几何规划分支并复用模型，不打开 PL 加速器、不重新识别整个汉字、不搜索 3500 字库。保留七轴连续性、关节限制、碰撞、纸面边界、下压上限和笔轴姿态检查。

下发前按照现有 SDK 的四位小数与 float32 格式处理关节目标；对最终合并段重新检查实际关节插补路径。`executor.py` 使用现有华成 `moveJoints` 与控制器插补，完成条件同时包含队列回调、运动状态和末端/关节反馈。接口返回成功不等于实际运动完成。

本版本没有改用尚未联调的 `PluseToServo`，也没有声称控制器执行了 CPU 的 4 ms 时间戳轨迹。执行速度遵循现有全局速度策略，模板 feed 曲线目前作为元数据保留；实际速度变化取决于控制器插补和路径，不能称为逐点力控或精确时间曲线。压力通过下压深度表达，不是力传感器闭环。

现有毛笔毛长 9 mm、直径 2 mm、已配置下压上限 4 mm；此次未改变工作高度、纸面标定或归位点。

## 验证与性能

离线测试覆盖双模板映射、CPU 无 PL 访问、40/100 mm 轨迹、队列顺序、并行规划、停止、失联、切字、旧结果作废、回调提前到达以及界面权限。浏览器端模拟测试覆盖真实指针输入、排队、刷新保留、切字、停止和返回。

板端使用当前实机配置但不连接控制器的 12 条 CPU 测试结果见 `build/handwriting_20261023/board-benchmark-optimized.json`：40/60/100 mm 下横、竖、撇、横折的识别加规划约 0.47～1.17 秒。该时间不包括真实触摸抬手采集、HTTP、SDK 下发、机械臂开始运动和移至起笔点；不是实测端到端响应。复杂笔画、负载、起始姿态变化可能增加耗时。尚未达到“所有笔画百毫秒级起动”。

实机的落纸效果、书写中队列和端到端响应尚待现场验收。本次部署验证不自动进入手写模式、不使能、不发送绘画指令。

## 构建、部署与回退

在板子新版本目录执行 `python scripts/build_handwriting.py` 编译 ARM32 CPU 识别库。现有七轴本地规划库和 FPGA 文件沿用，原始代码仍随工程保存。

版本目录：`/home/xilinx/tcb705_releases/20261023_handwriting_r1/ZYNQArm`。
上一版本：`/home/xilinx/tcb705_releases/20261022_text3500_r1/ZYNQArm`。
本机部署工具：`scripts/deploy_handwriting.py`，分 `stage`、`test`、`activate` 三步，先校验文件与离线测试，再切换服务。配置和数据仍位于 `/home/xilinx/tcb705_data`，云端密钥不打入更新包。

回退时先确认没有运行中的机械臂任务，将两个服务目录 `tcb705-ui.service.d`、`so101-md0700r.service.d` 内本次新增的 `zzzzzzzzzzzzzzzzz-handwriting.conf` 改名为 `.disabled`，把 `/home/xilinx/ZYNQArm` 链接恢复上一版本，再 `systemctl daemon-reload` 并重启 `tcb705-ui`。不要重启 PL 平台服务，不要删除当前校准数据。
