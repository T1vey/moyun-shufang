# TCB705 机械臂运动改为华成 SDK V2.4.1 控制（2026-10-20）

控制器固件已升级到 1.9.84（SDK V2.4.1 要求至少 1.9.82）。绘画、归位、停止后归位的**运动指令**都改为通过 SDK 下发，不再“下载控制器程序 + 按运行键”。

## 结构

| 部分 | 文件 | 说明 |
|---|---|---|
| SDK 服务程序 | `native/huacheng_bridge/sdk_server.cpp` → `build/tcb705/tcb_sdk_server` | 板子的 ARM32 `libxoip.so` 没有 Python 绑定，所以用一个小的 C++ 程序，按行收发命令 |
| Python 客户端与运动后端 | `tcb705/sdk_motion.py` | `SdkClient`（协议）、`SdkMotion`（把程序块翻译成 SDK 指令）、`live_speed()`（绘制中改速） |
| 执行流程 | `tcb705/web_executor.py` | 规划、归位、路径看门狗都不变；运动部分换成可插拔的 `motion`（`ProgramMotion` = 原控制器程序方式，`SdkMotion` = SDK） |
| 选择 | `tcb705/bridge.py` | `execution.sdk.enabled=true` 时走 SDK |

指令对应关系：

- `hmcRobotFree` 块 → `RobotManager::moveJoints`：下发本地七轴 IK 解出的关节角，单位为度。
- `hmcLine` 块 → `RobotManager::moveLine`：归位时先竖直抬起，再平移。
- 速度 → `RobotManager::setGlobalSpeed(0..100)`：开画时设置一次，绘制中可以随时改。
- 停止 → `RobotManager::clearRobotRoute(急停)`，同时保留原来的 Web 停止作为备份。

位置、状态、报警的读取和手动/自动模式切换仍然走控制器 Web API，原因是今天 SDK 的 `getJoints`/`getWorlds` 读不到数据。

## 速度调节（板子上）

- 主界面顶栏新增“速度 − 10% +”。小于 10% 时每次调 1%，其余每次调 5%，松手约 0.5 秒后保存。正在绘制时，这一幅也会立即改速。
- 设置页的“机械臂速度”（0～100，不能为 0）改为调用 `/api/tcb/speed`，绘制中也可以保存。
- 速度不进入规划摘要，所以改速后已有规划仍然有效。

## 安全

- 每次最多 `queue_depth` 条指令在控制器里排队，默认 1 条：等上一条完成回调后再发下一条。
- 控制器拒绝指令（返回 1）或报告未完成时，立即停止，**不会重发**。
- Python 进程意外退出时，服务程序检测到输入断开，会先 `clearRobotRoute` 再退出。
- 不清报警，不改保护设置，不用 `PluseToServo` 透传（透传要求关闭保护）。
- 原有检查全部保留：起点核对、路径偏离、低于纸面、无进展、离纸 60 mm 才切模式。

## 配置（`tcb705_data/tcb705.machine.json`）

```json
"execution": { "sdk": { "enabled": true, "server": "build/tcb705/tcb_sdk_server",
                        "local_ip": "192.168.4.23", "port": 8001, "queue_depth": 1 } }
```

`local_ip` 是板子 `eth1`（接控制器的网口）的地址。改回原来的程序方式：把 `enabled` 设为 `false`。

## 尚未在实机验证

1. 板子上的 SDK 与控制器之间的连接。今天控制器网线插在电脑上，板子的 `eth1` 没有连上。
2. `queue_depth>1` 时，控制器是否会排队并平滑衔接连续的 `moveJoints`。验证前保持 1：每段之间会短暂停顿，但不会出错。
3. `setGlobalSpeed` 对 `moveJoints` 的实际速度比例，以及绘制中改速是否立即生效。
