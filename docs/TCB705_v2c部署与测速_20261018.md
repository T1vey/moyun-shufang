## 实际性能

输入为 `examples/motion_portrait.paths.json` 前 8 笔，0.5 mm 节点间距，相同配置及离线求得的起始关节角。每轮 1,569 个节点、1,568 个 IK 目标、25 个批次。三轮均保持生产路径、姿态、碰撞和动力学校验，没有连接机械臂。

| 指标（三轮中位数） | ARM CPU | FPGA 路径 |
|---|---:|---:|
| 总规划耗时 | 11.935 s | 13.955 s |
| IK 调度累计耗时 | 0.546 s | 2.575 s |
| 每个 IK 目标耗时 | 0.348 ms | 1.642 ms |
| CPU 校验通过的 PL 行数/轮 | 0 | 1,568 |
| PL 拒绝/CPU 回退/加速器错误 | 0/0/0 | 0/0/0 |

FPGA 后端为 `ZYNQ_PL_7R_BATCH`。每轮 CPU/PL 的最大工具位置差约 `7.18e-8 m`，这是数值对照结果，不代表机械臂已达到该物理精度。首次 PYNQ 附加耗时约 6.87 s，单列在报告中，没有计入每轮规划计时。

额外一轮分项计时：IK 总耗时 2.614 s，DDR 写入/启动 0.114 s、等待硬件完成 0.122 s、读回/协议校验 0.273 s。约 2.105 s 在这些传输计时之外，包括主机端数据处理、逐行 FK/误差检查与调度，尚未进一步细分。

**当前整段规划仍比纯 CPU 慢约 17%，不能宣称实测达到理论 9 倍加速。** 后续应优先分析并优化主机处理和逐行检查的开销，同时保持全部数值门槛；只继续加速 HLS 内部运算不能解决当前主要开销。
