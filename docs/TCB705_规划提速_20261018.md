# TCB705 规划提速（参照 SO101-1013 批处理策略）

2026-10-18。起因：[v2c 测速](TCB705_v2c部署与测速_20261018.md) 中 8 笔人像 ARM 规划 11.9 s，IK 仅 0.55 s，其余时间耗在主机端逐点/逐段的 Python 与 numpy 小调用上。本轮只改计算组织方式，**不改任何步长、速度/加速度/jerk 限制、误差阈值、探测点数量和批次边界**。

## 参照的 1013 策略

SO101 的 `planner_source/r1b/continuous.py`：所有节点的多项式公式一次计算；探测样本按索引 gather 系数（`coeffs[indexes]`）后整批求值；网格复用；每个 1024 样本批次只做一次 FK 和检查。TCB705 已沿用批次边界，但批内仍按区间逐个 `polyval`、按段逐个二分，本轮补齐。

## 改动

| 文件 | 改动 |
|---|---|
| `tcb705/planner.py` | `coefficients` 去掉两重逐节点循环，改为整体掩码；相位时间分配的 45 步二分由「每相位 45 步」合并为全体 45 步（逐元素运算，结果一致）；几何探测改为批内一次 gather + Horner（`evaluate_rows`，运算顺序与 `polyval` 相同），批次边界仍 ≤1024；`line()` 一次生成全部细分点；拐角余弦按笔画整体计算；笔画排序端点距离向量化；`max(ndarray)` 改为 `ndarray.max()`（原写法在 58,943 帧上逐元素走 Python） |
| `tcb705/planning_batches.py` | `ChainDispatcher.next` 用轻量比较替代 `np.array_equal`；`PLChain.solve_chain` 对 PL 回传整批做 FP64 位置/姿态/限位校验（门限与原逐行 `pose_error`/`legal` 相同，仍从首个不合格行截断并记录拒绝原因）。这是 v2c 文档里 PL 路径约 2.1 s 主机开销的主要来源 |
| `tcb705/collision.py` | `check_batch` 将 16 对胶囊体一次计算（按 2048 行分块控制内存），首个碰撞行及报告的胶囊对与原循环一致 |
| `native/tcb_planner/core.cpp` | `tcb_fk_batch` 使用刚体专用乘法（不展开固定的 `[0 0 0 1]` 行，累加顺序不变）；模型或工具末行非精确 `[0 0 0 1]` 时退回原 `fk()`。单点 FK、Jacobian、IK 及 HLS 共用的 `math7.hpp` 未改 |

## 验证（PC）

`build/tcb705/compare_planner_speed.py` 在同一进程交替运行改前冻结代码（`build/tcb705/planner_speed_baseline_20261018/`）和新代码，逐字节比较全部输出：帧、float32 SDK 角、多项式系数、节点、预览、指标与错误信息。

| 输入 | CPU 原生 | PL 软件仿真 |
|---|---|---|
| 8 笔 0.5 mm（板端测速输入） | 逐字节一致，1.2–1.4× | 逐字节一致，1.6× |
| 12 / 16 笔 0.5 mm | 一致 | 一致，1.6–1.9× |
| 4 笔 1 mm、32 笔 2 mm（触发 CURVE_GEOMETRY） | 错误信息一致，2–3.5× | 一致，2.5–4.2× |

PC 上 numpy 调用开销很小，加速倍数会明显低于 ARM；cProfile 显示每轮 Python 函数调用由约 20.8 万次降到 10.4 万次。8 个 tcb705 测试模块 100 项通过（`.venv`），改前代码同样 100 项通过。**板端实际耗时尚未测量，不能用 PC 倍数推算板上秒数。**

## 板端部署（待执行）

1. 复制上述 4 个文件到板上发布目录。
2. 板上运行 `python scripts/build_tcb705.py`，重编 `libtcb_core.so`。
3. 用 `deploy/tcb705/v2c` 的流程更新补充哈希清单。
4. 运行 `scripts/benchmark_tcb705_portrait.py --repeat 3`，与 v2c 的 11.935 s（CPU）/ 13.955 s（PL）对照，同时检查 CPU/PL 几何对照仍通过。

回退：用 `build/tcb705/planner_speed_baseline_20261018/` 中的 4 个源文件覆盖并重编。
