# 绘画路径修复版（2026-10-04）

当前状态：电脑端代码、完整软件包和离线验证完成。电脑未连接板卡，新版尚未安装到板端，未进行真实纸面绘画验收。现有 Vivado 2024.2 目标 IK bit/hwh/map 可继续使用。

## 修改后的行为

- GUI 与 HTTP 图像入口共用 `vision.convert`。细黑线提取中心线，使用图边访问记录避免往返与重复描线；真实相邻平行线保留。
- 无分岔连续曲线合为单笔。分岔处按切向连续性连接，剩余分支另起笔，每条图边只访问一次。
- 按几何包含关系先外后内；开放的鸭子头部弧线只在判断包含时虚拟闭合，实际轨迹不添加闭合直线。
- GUI 保持原有完整画布尺寸和 y 方向，避免切换算法后镜像。HTTP 原有 y 向上惯例保留，两者在数据中明确标注方向。
- 超过线段预算拒绝整次提取，避免只保留前半张图。
- 新增实际笔画预览：编号、起点、抬笔虚线与顺序播放。云端图片预览明确标为原始线稿。
- 板端重新计算上传笔画数量，检查坐标与摘要，并直接生成对应 SVG。
- 连续规划恢复批量 FK：全部命令采样点与每段 17 个探针。落笔路径与笔轴超出配置容差时返回 `DRAW_GEOMETRY_ERROR`，不提供可执行命令。
- 分开报告到预期线段的几何距离与按时间指定目标的距离，保留舵机时刻和位置计算方式。
- 保存源图、笔画摘要与流程版本。旧流程历史规划保留供查阅，但真实执行需要重新提取、重新规划。
- 新 GUI 检查板端流程版本；仅更新电脑端时会提示安装板端新版。

纸面接触、笔尖弯曲、机械间隙和实际跟随不能通过离线算法验收。此次没有修改纸面/工具标定或舵机参数。

## 使用

电脑端离线查看：

```powershell
python scripts/arm_studio.py --target-drawing --offline --no-tunnel --image tests/fixtures/duck_lineart.png
```

点“提取笔画”会先显示离线实际笔画，再尝试登记到板卡。板卡未连接时登记失败，旧规划不会被恢复为当前可执行规划。也可指定 `--preview-paths <paths.json>` 直接显示已提取结果。

板端接通后，在当前工程根目录执行：

```powershell
.\deploy\deploy_z20.ps1 -BoardIP 192.168.2.99 -Python "C:\Users\gongj\AppData\Local\Programs\Python\Python312\python.exe" -Profile target -OverlayDir "C:\fpga_build\so101_target_2024_1003\export" -Offline -AllowMotion
```

部署脚本使用已有匹配 bit/hwh/map，不启动 Vivado。它会新建发布目录，保留 `/home/xilinx/so101_data/machine.json` 和作业资料；有运行中的任务时拒绝切换服务。安装会复核目标 IK 硬件，但不发送舵机运动命令。

部署成功后打开新版 GUI，重新选择图片 → 提取笔画 → 看顺序预览 → 用真实模式重新规划。旧历史规划需要重建。实际测试由用户控制启动，先观察小范围曲线与抬笔转移。

## 已验证与待验证

同一鸭子原图，100×100 mm 完整画布：旧版 12 笔、526 段、2052.8 mm；新版 9 笔、216 段、516.0 mm，落笔路径减少约 74.9%。外轮廓第 1 笔，左右眼各一条开放曲线。

归档的机器配置与固定起始计数、电脑端原生目标 IK 库：100 mm 鸭子规划成功，524 目标、3274 命令；模型落笔路径最大偏差约 0.159 mm，计数量化后的目标误差约 0.493 mm。这些结果来自电脑离线运行，不是当前板端时延、编码器实测或纸面误差。

独立回归覆盖直线、开放弧线、闭合圆、T 分岔、交叉、嵌套轮廓、平行线、空白、超预算、摘要不一致和旧规划执行拒绝；真实 Tk 窗口部件的隐藏构造/预览检查通过。

待板端连接恢复：安装新版、读取当前配置、验证启动版本与 85 组 PL 数值、重新规划并记录阶段耗时，再进行实际落笔/跟随与纸面还原测试。不得将离线路径改善直接换算为 FPGA 规划提速或实际绘画提速倍数。
