## 已实现的改进

1. **跨运动小段合并计算。** 五次多项式系数和全曲线导数上界一起计算。将原来每个小段单独进行的 FK 调用合并为最多 1,024 个点一批；同一插值结果同时用于几何检查和指令生成。相同数量的采样网格复用。测试人像的 24,969 个几何检查点从 1,193 次 FK 调用合并为 25 次。
2. **笔轴批量球面插值。** 每段验证轴端点、计算夹角一次。所有对应采样点一起计算轴方向，保留接近同轴和转轴的处理，拒绝未指定中间轴的反向过渡。
3. **静态 IK 输入复用。** 缓存已验证的连杆、轴、工具、关节限位、权重和求解配置。每次比较包含形状与精确字节的键，修改现有数组也会重新验证。每个新目标的位置、笔轴、初始关节角仍逐点验证。
4. **减少 AXI 静态写入准备。** 相同配置下只准备本次变化的初始关节角、目标位置及笔轴寄存器。保留现有寄存器映射、状态/ABI/迭代检查、超时后禁止复用的处理。
5. **减少小向量计算开销。** 三维姿态误差使用标量算式。轴序列严格等于 SO101 的 Rz/Ry/Ry/Ry/Rx 时，单点 FK 使用标量变换链，仍使用完整工具和连杆参数；其他轴序列继续使用通用 FK。批量 FK、Jacobian 和独立齐次变换对照保留。
6. **计数量化批量计算。** 与执行器完全相同的算式顺序和 ties-to-even 舍入，逐关节检查计数限位，再批量计算所有指令的 FK。半计数及其两侧浮点数已与原执行器逐项对照。
7. **诊断记录减少递归复制。** 保存返回结果的完整历史字段，复用结果已经拥有的列表；历史规划仍保存独立机器、路径和绘图快照。
8. **耗时显示更准确。** 新引擎标识为 `planning-speed-v2`。GUI 显示本次 30 秒目标是否达标；`pl_job` 记录本次调用的写入、等待、读取、校验耗时，避免把整个服务会话的累计耗时当作本次规划耗时。
9. **明确历史保存结果。** 保存器返回实际结果，失败时不会报为已经持久化，GUI 提示计划只能在当前服务中使用。计时工具报告三轮中位数、最小值和最大值，以及进程 CPU 时间；Linux 板端附带进程峰值 RSS（累计高水位，不等于单任务新增内存）。

## 保留的精度与覆盖

本轮没有增大笛卡尔步长、减少原有命令点、改变速度/加速度限制、放宽误差阈值或减少连续曲线探测点。每个小段的所有命令采样点及 17 个区间探测点均检查。IK 返回的每个成功解仍由 PS 独立计算 FK，再核对位置/笔轴误差和 PL 回报误差。

预测 GUI、每条线段顺序、云端图片库和历史规划快照功能均包含在新版运行包中。原有比特流与 AXI ABI 保持一致，本轮更新 PC/板端 Python 软件即可。

## 板卡连接后的验收

1. 安装本轮运行包，保持当前标定；确认 GUI 后端为 `PL_z20_ik_target`，规划引擎为 `planning-speed-v2`。
2. 从云端图片库选择该人像，设置 100×100 mm、lineart/fine。查看路径预测，应为 36 笔、474 段。
3. 保持机械臂同一初始姿态，连续三次点击“规划”。每次新建规划，不选择历史计划。仅规划不需要执行绘画。
4. 保存三次 `timing.json` 和规划日志，检查全部 `job_ready_s ≤ 30`，同时要求状态 OK、轨迹误差/限位检查通过。`job_ready_s` 包含串口预检、完整轨迹生成与历史保存；GUI 的轮询/传输延迟另外观察。
5. 查看“已规划轨迹预测”，核对线段顺序与整幅效果，再进行实物绘图验收。

也可使用包内 `scripts/benchmark_planning_speed.py` 进行冻结输入的板端对照。PL 模式会加载 overlay，运行前应确保没有正在绘画或规划的任务，并停止服务以独占该 IP；测试只规划与保存，完全不访问舵机。参数 `--paths`、`--machine`、`--q0` 指定保存的路径、机器配置和五维起始角 JSON，`--overlay` 指向现有 `drawing_target.bit`，`--runs 3 --output <目录>` 保存每轮报告。此脚本测量 build 与历史保存，不包含 HTTP 和串口预检，最终 GUI 验收仍使用 `job_ready_s`。

30 秒目标针对有明确尺寸、标定、起始姿态和目标点规模的输入。不同图片的笔画数、抬笔移动、求解恢复次数与输出指令数会影响时间，因此本轮 PC 提速倍数不能直接作为 Zynq 板端秒数。
