# 手写单笔低延迟：实测与实现状态

日期：2026-10-22。项目：`D:\zhiliao\TCB705_ZYNQ-10-15\ZYNQArm`。

## 结论

手写短笔画采用 ZYNQ PS 上已有的 C++ 七轴连续逆解是一条合理路线；无需每笔经过 PL。
在板上 CPU 计算测试中，40 mm 横笔的悬停场景，281 个几何节点的批量 IK 用时约 28 ms。
仍然使用完整现有规划器时，整笔准备约 0.94～0.97 s。不能把 28 ms 说成松手到机械臂运动的响应时间。
本轮没有在同一条件下对比 PL 性能，因此没有证明 CPU 对任意轨迹都比 PL 快。

## 已完成的代码

- `tcb705/model.py`：七轴角度转换批处理，保持轴序、符号、偏置和原运算顺序；拒绝非有限值。
- `tcb705/artifact.py`：将节点一次转换为 SDK 角度，避免每个节点跨 Python 调用。
- `calligraphy/execution.py`：批量计算候选关节段的正解和毛笔检查，保留原均匀采样及压力拐点采样，不放宽误差。候选跨越笔画阶段或停点时仍拆分。
- `tcb705/web_executor.py`：一次准备共用模型；复用合并细化时已完成的同一组毛笔几何检查，保留独立的关节段路径误差检查。
- `tcb705/planning_session.py`：新增 `plan_cpu(...)`，明确走原生 CPU，不触发 PL attach、DMA 或 FPGA 初始化；没有更改现有 `plan(...)` 默认行为。
- `tcb705/planning_batches.py`：分别记录原生 CPU/PL 批量 IK 时间，便于后续选择后端。
- `scripts/benchmark_brush_latency.py`：可重复执行的纯计算基准，支持假定悬停场景。

板端的批处理、毛笔合并、执行准备共 16 项回归通过；新增 CPU 会话入口另有 5 项会话测试通过。本机另通过 17 项归位/停止相关测试。
检查覆盖错误映射、姿态、过压、纸面越界、空走触纸、压力峰、停点和阶段边界、缓存失效与取消。

## 下一步的低延迟链路

1. 进入手写会话时加载模板、初始化模型和通信；只在会话入口执行需要的归位及就绪检查。
2. 触摸期间持续采集、去噪和分类。纸面映射固定，不能因笔画包围盒变化把已规划的整条路径重新缩放。
3. 松手后选择最近模板，自动生成该笔的笔锋/下压安排。若最终分类改变了压力曲线，相关关节轨迹必须重算；不能把预测结果直接当最终结果。
4. CPU 原生 IK 用上一有效关节解作为种子，保持局部连续；实际执行前核对起点。
5. 为 SDK 实际接收的关节段建立专用规划路径。当前 C2 曲线和 4 ms 帧仍被生成；不能仅删除它们的检查，而应验证真正下发的关节插值、SDK 舍入、限位、笔轴、下压、纸面范围及碰撞等约束。
6. 使用持续运行的 C++ SDK 发送器，完成一笔后抬笔悬停，接受下一笔。维持有界队列、顺序号、停止和断线处理，不自动重放旧命令。
7. 记录触摸松手、最终规划完成、SDK 接收、反馈开始运动四个时间点。测量后再给出响应承诺。

尚未测出 CPU/PL 单笔切换阈值。短笔画先用 CPU，整图/多字长任务保留现有 PL 路径；阈值应根据相同输入、热启动条件下的端到端数据决定。

## 关于 FPGA 直接发给机械臂

现有 GE_PL 是 PS GEM1 经 EMIO、PL GMII/RGMII 桥连接 PHY，参见 `hw/ge_pl/apply_ge_pl.tcl`；它不是独立的 PL 机器人网络发送器。
现有 PL ABI 提供 IK_CHAIN/FK_ROWS，完整规划仍包含 CPU 工作。
SDK 下发通过 `RobotManager::moveJoints` 等接口，包含连接、完成回调、状态等约束。ARM 预编译 SDK 不能直接综合成 FPGA 逻辑。
完全硬件化需要控制器的完整网络命令协议和队列/时序规范，以及 PL MAC、所需协议栈和状态机；只连接关节角 FIFO 到网口并不能工作。
对目前手写短任务，先优化 CPU 规划和持续 SDK 会话更直接；目前没有证据表明网络发包是秒级等待的主因。

## 2026-10-22：真实机械臂空中响应测试

用户明确只允许空中运动、暂不落纸。本轮已使能 TCB705，使用板端 CPU 原生 IK 和 SDK 完成四次约 5 mm 的 Y 方向往返。恒定高度约为控制器法兰 Z=315.5 mm，相比现有接触标定 Z=219.3 mm 高约 96.2 mm。没有修改机器配置、纸面或毛笔参数，也没有执行 `short_stroke` 的研究候选。

此处是独立的简单直线测试，不是完整的手写笔画识别入口。SDK、模型和使能在计时前就绪；模拟松手后执行 21 点连续 IK、实际舍入关节段的 129 个采样检查，再通过 `moveJoints` 发送一个不混合的关节段。速度采用 GUI 保存的 60%。计算检查保留 60 mm 离纸下限、8 mm 移动包络、1 mm 高度带、关节限位及碰撞检查。第一轮测试因完成回调后反馈尚未接近终点而停止；随后调整测试程序，使结束条件同时等待实际位置进入原有 0.3 mm 终点阈值，没有放宽该阈值。

平均约 203.4 ms。最后一列包含 SDK 命令应答时间，不能重复相加。运动到反馈满足结束条件约 429～484 ms。四次样本不足以代表尾延迟、最坏值或其他笔画。

测量限制：SDK `getJoints(..., true)` 本次能读取实际关节反馈，单次往返约 1～2.4 ms，但运动期间不同反馈值通常相隔约 50 ms。因此它读取的是周期刷新的反馈，不能据此声称物理起动时刻精确到毫秒，也不能直接从结果减去 50 ms 当作物理起动时间。首次越过阈值时所见位移为 0.23～0.75 mm。真正的物理起动时间还需同步视频/外部传感器或带采样时间戳的更高频反馈确认。

这些结果不包含触摸松手事件、笔画分类、40～70 mm 毛笔模板及压力规划、移动到真实纸面和落纸。不能把本轮 0.2 秒称作完整“松手到落纸书写”时间，也不能直接替换前面的完整毛笔规划数据。
