# TCB705 执行前轨迹准备提速（2026-10-20）

## 原因与改动

点击开始后，旧执行器还要对整幅图运行 `joint_merge` 和
`joint_block_error`，之后才上电、等待静止及归位。FPGA 加速的是前面的
IK；这两项是 ARM 上的 CPU 计算。

本次将相同的贪心合并、节点检查、7 个额外合并探针和每段 15 个误差探针
迁入 CPU C++ 核，消除逐候选段的 Python/Numpy 分配及 ctypes 调用开销；
SDK 角度映射也改为整批转换。仍保留 Python 回退路径，旧 CPU 库仍可运行。
没有放宽误差容限，也没有减少检查采样点。

实机规划在预览就绪前完成这项纯计算，保存不可变的内存准备结果。
执行时验证配置、模型和全部节点的摘要；改变几何、标定、阶段、停止点或
合并/校验容差会使缓存失效并重新计算。速度和分块设置不复用旧运动块，
而是用当前设置重新生成运动块。

控制器状态、报警、当前位置、上电后稳定检测仍在执行时读取；不缓存实时状态。
新增上电前取消检查。执行结果保存 `preparation.cached`、
`preparation.seconds` 和 `preparation.precomputed_seconds`，避免长任务日志
仅保留最后 50 条而丢失准备耗时。

## 板上离线对比

输入：最近任务的同一份笔画和配置，在电脑离线重建的 21,680 个几何节点；
在板子上对新旧准备算法使用完全相同的节点。并非重新执行一次画画。

| 项目 | 耗时 |
| --- | ---: |
| 原版构建运动块 | 83.943 s |
| 原版插补误差校验 | 12.917 s |
| 原版合计 | 96.860 s |
| 新版预计算与校验 | 5.858 s |
| 命中缓存后摘要核对及生成运动块 | 1.153 s |

原版与新版产生的 2,483 个运动块（含全部命令内容）完全相同。
最大误差也相同：近纸面 0.049630845395 mm，空中 0.172175453896 mm。
新版预计算加生成块合计约 7.01 s，约为原来的 1/13.8；
预览已准备好时，点击执行后的这一计算部分约为 1.15 s。

这些是计算耗时，不是“点击到机械臂实际运动”的整段时间；
SDK 连接、控制器通信、上电稳定和归位仍然需要时间。
本次基准没有连接控制器、上电或发送任何运动指令。

原始数据：`build/tcb705/startup_speed_20261020/board_benchmark.json`。
本地修改前备份：`build/tcb705/startup_speed_20261020/before/`。
板上隔离测试目录：`/home/xilinx/tcb705_preparation_benchmark_20261020/`。

## 回归范围

新增 `tests/test_tcb705_preparation.py`，覆盖原生与 Python 路径等价性、
非恒等关节映射/基坐标变换、阶段边界及停止点、缓存失效、
速度变化后的运动块重建、报警拒绝和上电前取消。
执行测试使用模拟控制器。

验证结果：电脑端 `test_tcb705*.py` 共 82 项，通过（1 项原生新接口测试因
本机 DLL 尚未重编译而跳过）；板上新原生库的 Web 执行及准备回归共 39 项，
全部通过，无跳过。板上原生与 Python 对比还覆盖非恒等轴序、符号、零位和
基坐标变换。电脑现有 DLL 使用兼容的 Python 回退路径。
