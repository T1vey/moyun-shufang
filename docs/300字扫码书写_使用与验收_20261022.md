# 300 字扫码书写：使用与验收

日期：2026-10-22。代码已完成；按用户要求，本轮仅完成本机工程和离线验证，没有连接板子、部署服务或驱动实物机械臂。

## 使用流程

1. 后续部署后，手机连接板子所在网络，扫描主界面原有二维码。
2. 选择 **毛笔写字**，输入已收录的汉字。可查看完整 300 字清单。
3. 调整字号 **40～70 mm，步长 1 mm**，点击 **预览排版**。
4. 核对内容与页数，点击 **提交并开始书写**。板子本地生成有序笔画、完成整页七轴规划，通过检查后自动启动。
5. 每页开始前归位，每页完成后归位；多页任务等待用户换纸并固定在相同位置，再点 **已换好纸，继续下一页**。手机和板端均有继续按钮。
6. 需要停止时点 **停止书写**，沿用现有停止后归位逻辑；再次停止可以中止归位。

本地模拟界面会明确显示“模拟”，按钮为“提交并模拟书写”。模拟不会连接或驱动机械臂。

## 字号、方向与容量

按最新确认，使用现代横排：**从左到右，从上到下**。每个汉字保留数据源的中国大陆笔顺、笔画起止方向；不会为了少走空行程而重排或反转笔画。部件穿插、包围结构的收口顺序来自完整汉字的逐笔记录，不是先把一个偏旁全部写完再写另一个。

字号是正方形字格边长，不是笔迹包围盒宽度。字形保留原有字面留白。字号只缩放 XY，不按比例放大下压力。

四周留白 10 mm；横向间隔 max(4 mm, 字号×0.1)，纵向间隔 max(6 mm, 字号×0.2)。一行最多五格，并自动减少到标定纸面实际能容纳的数量。

以保存的约 **148.52×150.215 mm** 标定区域计算：

| 字号 | 每行 | 每页行数 | 每页字格 |
|---|---:|---:|---:|
| 40 mm | 3 | 2 | 6 |
| 50 mm | 2 | 2 | 4 |
| 60 mm | 2 | 1 | 2 |
| 70 mm | 1 | 1 | 1 |

支持空格、全角空格和主动换行；空格占一格。当前接受最多 200 个字符（含空格与换行）。首版暂不支持标点、英文、数字字符或未收录汉字，会明确提示缺少内容，**不会静默漏字或替换字形**。数字可以输入“一二三”等已收录汉字。

## 300 字字库的来源和实现

- `data/calligraphy/常用300字.txt`：实际收录清单。是常用、基础和祝福语试用集合，不宣称是统计频率前 300 名。
- `data/calligraphy/glyphs.sqlite`：只读数据库，300 字、2,014 笔，约 1.73 MiB。运行时按字读取，缓存至多 128 个字。
- `data/calligraphy/glyphs.jsonl`：可编辑、可重新构建的字形记录。
- `data/calligraphy/manifest.json`：字库版本、来源摘要、几何摘要、数据摘要和修改说明。
- 来源是现有 `maobi/chinese_caligraphy_robot/graphics.txt` 中的 Make Me a Hanzi 数据。原项目明确采用中国大陆笔顺；本工程保留每字的 `medians` 顺序和方向。
- 逐笔中心线配合已有横、竖、撇、捺、点、提、折钩等模块的提按包络，生成平滑曲线；折笔不拆成多个独立笔画。
- 这批是可执行的首版工程轨迹，**尚未逐字验证真实墨迹**。提按幅度、顿笔效果和毛笔弹性可以在实机结果出来后按字/笔进一步校正。不能把几何预览当作实物书法品质保证。

原字形许可和署名随数据提供：`APL-English.txt`、`COPYING.makemeahanzi`。每条修改后的字形记录也包含来源和修改日期；手机字库详情可查看许可。参考：<https://github.com/skishore/makemeahanzi>。

## 接入现有工程的位置

| 文件 | 功能 |
|---|---|
| `calligraphy/glyph_store.py` | 只读 SQLite、受限缓存、字库版本 |
| `calligraphy/text_layout.py` | 标准横排、40～70 mm 边界检查、自动换行和分页 |
| `calligraphy/composer.py` | 逐页展开有序 XY / depth / feed，生成字与笔画映射 |
| `calligraphy/presets.py` | 新增 `brush-text-v1` 的服务端重建校验，保留原模块 |
| `user_gui/text_workflow.py` | 手机任务归属、预览、启动意图、分页、取消、重复提交保护 |
| `user_gui/workflow.py` | 复用原任务锁、七轴规划、执行和停止归位链路 |
| `user_gui/display_server.py` | 专用手机 API、配对码和同源验证 |
| `user_gui/static/mobile.html`、`text-writing.*` | 手机文字输入、字号、金色轨迹预览、状态和换纸 |
| `user_gui/static/desktop.*` | 屏幕页显示当前页预测图、继续下一页 |
| `tcb705/workbench.py` | 用文字请求生成内部笔画任务，然后复用现有 planner |
| `tcb705/planner.py`、`artifact.py` | 保留笔顺、冻结文字元数据，校验字库/标定版本 |

手机接口：`GET /api/text/capabilities`、`POST /api/text/preview`、`POST /api/text/submit`、`GET /api/text/status`、`POST /api/text/cancel`、`POST /api/text/next-page`。

预览不启动运动。提交需要当前手机的预览票据和明确的开始标记；更改内容、字号、标定或字库版本会使旧预览失效。手机只能提交文字任务，不能上传任意关节角或调用 SDK。保留原照片上传入口及其屏幕确认流程。

每个请求有固定编号，同一请求重复到达不会再画一遍。接收记录保存到数据目录的 `text_requests/`，服务重启后不自动续写或重写。规划和执行在后台线程进行，界面只读取状态；页面只绘制当前页 Canvas，不把数千个 SVG 节点放到触摸屏。

## 保留的实机设置

没有修改当前工作高度、纸面标定、工具/TCP 模型、4 mm 实测下压上限设置、机械臂连接地址或全局 GUI 速度。现有笔画/偏旁模式继续可用，顿笔缩时和统一速度逻辑继续复用。

没有新增 FPGA IP，也没有替换 bit/hwh。汉字数据读取与排版在 ARM CPU 执行；新文字轨迹仍进入原规划链路，在正常板端平台下复用已部署的 PL 七轴加速能力。本机离线验证使用 CPU 原生逆解。

## 验证结果与边界

1. **111 项自动测试通过（分批执行）**：所有 300 字在 40 / 70 mm 两端生成、数据重建校验、越界/缺字/NaN 拒绝、正常横排、分页、重复点击、其他手机拒绝、取消、断线不重放，以及原有书法、速度、归位、图片界面回归。首轮 108 项通过；补充 3 项后重新运行受影响的 64 项，全部通过。
2. **350 组真实七轴算法离线检查通过**：所有 300 字按 40 mm 排成 50 个六字页面，再对每字作一次 70 mm 单字规划。使用工程保存的 2026-10-20 天链模型/标定快照与保存的归位关节姿态，没有读取实时机械臂。
3. 350 组中的最大计算路径误差约 **0.0396 mm**。这是规划器 FK/IK 的数值校验误差，**不是实物精度**。实际误差还受模型、TCP、纸面、机械结构、墨水和毛笔影响。
4. 其中 6 组还通过关节段合并、毛笔几何校验及控制器程序构建检查；没有调用真实运动接口。
5. 实际 HTTP 服务完成“两页文字 → 自动规划 → 模拟执行 → 换纸等待 → 第二页完成”；同请求重复提交未产生重复任务。手机页面已做浏览器视觉检查。

报告在 `reports/text_calligraphy_20261022/`：`regression.txt`、`final_delta_regression.txt`、`native_library_verification.json`、`http_smoke.json`、`mobile_preview.png`。

板子重新连接后，仍需部署、触摸屏与手机扫码联调，以及“十、日、国、福”等少量字的真实墨迹验收。当前纸面矩形不保证任何新标定都可达：整页必须通过逆解和几何校验才开始，不允许删掉不可达笔画后继续。

重建字库（只读已有资料，不下载训练数据或演示素材）：

```powershell

```

使用保存的归位模型做离线批量校验：

```powershell
.\.venv\Scripts\python.exe tools\verify_text_library.py --profile build\tcb705\startup_speed_20261020\machine.json --report reports\text_calligraphy_20261022\native_library_verification.json
```

当前完成版电脑演示：`http://127.0.0.1:8098/`，手机页使用该演示界面的二维码/配对地址。演示配置在 `build/text_calligraphy_20261022/demo.machine.json`，起始关节设为保存的归位姿态；它仅用于模拟，**不要复制为板端实机配置**。

更新包：`dist/text_calligraphy_300_20261022.zip`，包含更新文件、字库、许可、测试和文件 SHA256 清单。部署前确认板子没有在绘画或等待换纸，备份清单中的旧文件；解压到实际运行的 ZYNQArm 工程，执行测试，再重启 `tcb705-ui`。本更新包不含机器配置、凭据、bitstream 或启动分区文件。版本不匹配时整包回滚，不能只换字库或只换 UI。
