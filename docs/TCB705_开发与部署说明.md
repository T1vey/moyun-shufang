## 1. 当前交付边界

这是前一份《TCB705机械臂ZYNQ主控绘画项目代码实施方案》的首个可运行实现。图像和业务层沿用 SO101 工程，运动规划已经使用独立七轴模型与算法。计算最密集的 FK/Jacobian/IK/批量 FK 在 C++ 中；路径编排、五次曲线、极值校验和任务管理当前在 Python/NumPy 中。尚未把全部路径和时间规划移入独立 C++ 规划进程，也尚未实现 Unix socket 常驻实时运动服务。

真实 `PluseToServo` 下发、保护状态切换、完成反馈、断流停机策略没有凭空实现。`bridge.execute(simulation=False)` 明确失败；`tcb_runner` 只接受模拟参数，二进制没有链接厂商 SDK。只读探测工具单独链接 SDK，不包含使能、清报警、运动或保护切换调用。这是当前代码的功能边界，不是实机验收已完成的宣称。

## 4. 坐标与连续逆解

内部单位是米、弧度、秒；输入笔画是毫米。支持 `full_canvas_xy_up` 和 `full_canvas_xy_down`，后者明确做 Y 翻转；未知坐标系、非有限数、超出纸面的笔画直接拒绝。

`T_controller_base_from_model` 将 URDF 基座变换到控制器基座，未填写时为单位阵；FK、Jacobian、批量 FK、IK 和碰撞框架使用同一变换。`T_flange_tcp` 表示 flange→笔尖，示例长 80 mm 仅用于演示。`tool_rotation` 是目标工具相对控制器基座的完整旋转矩阵，工具 +Z 必须指向该坐标 -Z；实际控制器坐标与重力方向仍需现场确认，不能宣称靠默认矩阵实现真实铅垂。

每点目标保留固定的完整工具姿态。IK 用上一点关节解作为 seed/reference，采用带阻尼和参考项的加权最小二乘，SO(3) 旋转误差、每步限幅、关节限位和回溯。相邻解超过 `max_joint_step_rad` 或求解失败时，递归细分笛卡尔路径；超过预算后停止规划并返回笔画和阶段，不跳到任意新分支。七轴冗余当前通过参考姿态正则约束，尚未加入专门的肘角最优化、全局分支搜索或限位避让代价。

SDK 角度适配独立于 URDF：`q_sdk[i] = (q_model[order[i]] - offset[i]) * sign[i] * 180/pi`。J5/J6 URDF 轴为负 Z 不代表 SDK 的 sign 必须取负，需要 FK 对照和实际反馈确认。

## 5. 抬笔、速度和精度处理

各笔连续串成一个完整时间轴：TRAVEL → LOWER → DRAW → LIFT。LIFT 固定 XY，沿世界 Z 增加配置高度；ArmVision 原值为笔间 0.008 m、最后一笔 0.060 m，最后高度从纸面起算，不叠加 8 mm。下笔固定新起点 XY。

起点必须已是竖直姿态，且至少具有配置中的笔间净空。当前不自动从任意停车姿态找无碰撞入场路线，也不在图画结束后自动回到起点。独立 demo 保留原来的 30 mm 升降，仅作数值验证。

使用共享速度/加速度的五次 Hermite 关节曲线，阶段交界导数为零，位置/速度/加速度连续。大于 30° 的真实折线角点局部起停，平滑曲线的普通采样点不中断。按关节速度、加速度、jerk 多项式极值对每个起停段独立放慢，不设置额外停顿。当前未实现轮廓误差容许范围内的圆角混合，所以尖角处必要的减速仍然存在。

验证分两层：

1. 多项式区间：精确计算关节位置及导数极值；对 FK 路径、工具姿态、升降单调和碰撞做细分采样校验。
2. 最终 4 ms 样例：关节角经过实际 float32/度转换，再转回模型 FK，验证每个发送样点的位置、姿态和限位；预测图使用这些 DRAW 样点。

姿态/几何和碰撞是数值采样检查，不是连续时间形式证明。真实伺服的插值、负载、刚度、零位和跟踪误差尚未测量。默认几何误差阈值 0.1 mm、姿态 0.0035 rad 是软件规划阈值，不是实机绘画精度承诺。当前障碍是简化胶囊和盒体；demo 关闭自碰检查并保持 `collision_model_verified=false`，不能拿 demo 配置直接运行实体。

## 6. 冻结计划和运行数据

每个任务存到 `<data-dir>/<session>/job_<id>/`。`paths.json`、`plan.json`、`trajectory.bin`、`preview.svg`、`result.json` 分别表示输入、元数据、采样轨迹、预测图与结果。历史最多恢复最近 10 个有效计划引用，恢复不会自动执行。标定/限位/轴映射等配置变化后必须重新规划。

二进制格式统一小端：

| 内容 | 格式 |
|---|---|
| 文件头 28 字节 | magic `TCBPLAN1`（8 字节）、version=1、dof=7、count、record_size=44、body_crc32，整数均 uint32 |
| 每帧 44 字节 | float64 相对秒，7×float32 SDK 度角，uint32 阶段，int32 笔画编号 |
| 阶段 | APPROACH=0、DRAW=1、LIFT=2、TRAVEL=3、LOWER=4、FINISH=5；首版实际使用 1..4 |

`plan.json` 包含完整冻结配置、其 SHA256、URDF SHA256、起点、时间周期、轨迹文件摘要与指标。当前上限 30,000 几何节点、150,000 采样帧，超过则报告预算错误。4 ms 下最大约 600 s；这不是控制器队列容量。限制用于约束 ZYNQ 内存，完整峰值 RAM 还需板端测量。

模拟器快放只检验完整轨迹格式并遍历，`timing_measured=false`，延迟统计为 null。实时模拟以 steady_clock 绝对时刻等待，但仍没有网络、SDK 调用或伺服；实时模拟通过也不等于 EtherCAT 周期验收通过。

## 7. 标定与只读联调

生成一份离线配置：

```sh
python3 scripts/tcb705_profile.py demo --output my-demo.json
python3 scripts/tcb705_profile.py validate --profile my-demo.json
```

默认配置为 `robots/tcb705/profile.armvision.json`，从 `D:/ArmVision2.0_User/backend/config/settings.yaml` 导入机器人 1 的 A/B、落笔 Z、UVW、8/60 mm 抬笔以及程序速度 100%。原三点标定命令和入口已经移除。详细表格、计算式和操作见 `TCB705_ArmVision标定说明.md`。

A/B 分别采集控制器世界坐标 X/Y；获取落笔点采集 Z/U/V/W。按原代码逐维排序 A/B，`swap_xy=true` 时使用 X=x_max-y/h×X跨度、Y=y_min+x/w×Y跨度，画面方向不变。界面保存后的配置在数据目录 `tcb705.machine.json`，变化使旧规划失效。控制器 IP 仍留空，Web 端口沿用 8010。

```sh
python3 scripts/tcb705_profile.py world --profile my-machine.json
python3 scripts/tcb705_profile.py feedback --profile my-machine.json
python3 scripts/run_tcb705.py --allow-real --no-browser
```

`world` 和页面标定采集读取原 ArmVision 的 Web 变量 `r_world_fb_pos_<robot>_<0..5>_`，不会使用示例 TCP 的 FK 代替。`feedback` 则通过 SDK 读取七轴，返回 `model_tcp_transform`，二者用途分开。所有反馈都只有主机接收时间，原 Web 接口逐项读取，采集时保持机械臂静止。

原软件依赖控制器已有 TCP/坐标设置；A/B+Z/UVW 不包含本地 URDF 与控制器的坐标对应、工具长度和关节零位。导入不会自动把 `calibration_verified` 置为 true。本地 IK 当前只接入 UVW=[180,0,0] 且 Tool/Coord/Extool=0 的约定；其他值能保存和采集，规划会明确拒绝，不会悄悄替换成默认姿态。

在 ZYNQ ARM32 Linux 上编译 `python3 scripts/build_tcb705.py --sdk`。SDK 适配源码直接使用配套 C++ 头文件及类，不用 ctypes 猜测 C++ ABI。本机 Windows 构建核心和模拟器；2026-10-17 已在板端编译核心、模拟器及 SDK 只读工具，动态依赖检查通过。尚未连接实际华成控制器验证通信。

## 8. 板端启动与显示迁移

新业务服务使用 8785/8095，数据建议 `/home/xilinx/tcb705_data`，密钥继续用现有私有文件，不写入模型或计划。依赖建议沿用板端 Python3.8 的 numpy/OpenCV/Pillow；若建 venv，使用 `--system-site-packages` 继承已安装的 ARM 包。对现有系统，先检测导入，再安装缺失包，避免无必要替换 PYNQ 依赖。

`deploy/tcb705/tcb705-ui.service.example` 是独立演示用的模拟模式模板。当前板端实际服务由 `install_board_service.sh` 安装，使用 `--allow-real` 与实际 ArmVision 配置，服务已启用；ESP8200 已连接。原工程保留，本轮未刷 FPGA、重启板卡或发送运动。`build_on_zynq.sh` 只构建和跑离线测试，不部署硬件。

已给原 `md0700r_display.py` 增加 `--user-ui-port 8095`：显示桥仍验证原密封 FPGA 平台及原 8765 硬件健康接口，只把 Xvfb 中的浏览器页面改指向新 UI，不加载旧 Tk 调试器。这样可复用原 RGB 通道与 GT911 触控链路。

## 9. 下一阶段真实执行工作

已有资料足以完成当前离线开发，不再重复索取“是否有上一点逆解参数”。本实现已经自带连续 IK。真实透传还需要在匹配控制器上完成：

1. 确认控制器/Host、robotId 和有效七轴配置，编译并运行只读工具。
2. 多组姿态与 SDK FK 对照，确认基座、法兰、TCP、轴序、符号、零位；完成纸面和环境配置。
3. 核实本机速度/加速度/jerk，以及 `PluseToServo` 周期、接收/执行返回、缓冲、超时、丢点和停止行为。
4. 按确认的契约编写真正 C++ 执行状态机：准备、初始反馈对齐、进入透传、绝对周期发送、监测、停止确认、最终反馈确认。发送与反馈的线程关系以 SDK 确认结果为准。
5. 空载低速短线→按标定高度升降→方框/圆→人像，独立验证纸面误差、笔杆角度和动态跟踪。长时间压力测试覆盖 GUI、上传、云端与日志并行负载。

当前代码没有将“最后一帧发送完”视为真实绘画完成，也没有将“停止发送”当成真实已停车。尚未有这些设备契约和实测结果时，无法诚实地给出实机可画的结论。
