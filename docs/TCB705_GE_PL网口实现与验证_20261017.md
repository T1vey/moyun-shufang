# TCB705 的 GE_PL 第二网口

## 实现范围

在原七轴 FPGA 加速、MD0700R 显示和 GT911 触摸平台上增加第二个 Linux 网口。
数据路径为：华成 SDK / Linux 网络栈 → Zynq GEM1 → EMIO GMII → AMD GMII-to-RGMII 4.1 → 板载 YT8531 → GE_PL。
GE_PS 和 Wi-Fi 继续用于原有连接。此次网络联调不发送使能、清故障、位置目标或绘画指令。

## 与原厂资料的对应

依据正点原子《领航者 ZYNQ 嵌入式 Linux 开发指南 V3.3》第 57.4～57.6 节，以及底板 V3.9 原理图 GE_PL 页。
原厂资料盘中的自定义 `gmii2rgmii:1.0` 模块与 Vivado 官方 IP 不是同一个模块。本工程采用官方桥接 IP 的 MDIO 速率管理方式，支持 10/100/1000 Mb/s，设备树也相应包含桥接器节点。

| 项目 | 本工程配置 |
|---|---|
| PS MAC | GEM1 / `e000c000.ethernet`，EMIO GMII |
| 外部 PHY | YT8531，MDIO 地址 4 |
| FPGA 桥接器 | AMD `gmii_to_rgmii:4.1`，MDIO 地址 8 |
| 参考时钟 | FCLK2，IO PLL 分频，200 MHz |
| RX 输入时钟 | 外部 RGMII RXC，按最高速 125 MHz 约束 |
| PHY 硬复位 | G15，低有效，PS EMIO GPIO 0，即 gpio0 offset 54 |
| 复位 GPIO Linux 编号 | 启动时查询 `zynq_gpio` 的 base 后加 54，不能直接当作 gpio54 |
| RGMII TX 时钟偏移 | 由板载 PHY strap 提供，FPGA 不再叠加 2 ns |
| 内核 | 当前板卡 `5.4.0-xilinx-v2020.2`，已有 macb / Xilinx GMII2RGMII 驱动 |

当前触摸由 `touch_pl` 模块和 AXI GPIO 数据包实现。早期工程注释中的 EMIO 0/1 触摸连接已被 `apply_gt911_pl.tcl` 移除，因此 GPIO 54 可单独用于 PHY 复位；不能把旧教程的 GPIO 63 原样抄入。

## 文件及构建

- `hw/ge_pl/apply_ge_pl.tcl`：可重复生成 GEM1、桥接器、时钟、复位和管脚连接。
- `hw/ge_pl/pins.xdc`、`timing.xdc`：板级引脚与外部 RX 时钟。DDR 输入输出时序由生成的官方 IP XDC 补充。
- `hw/ge_pl/ge_pl.dts`：独立设备树覆盖，外部 PHY 地址 4、桥接器地址 8。
- `scripts/build_tcb705_vivado.ps1 -GePl -ProjectDirectory ...`：新目录完整构建，保留旧工程。
- `scripts/package_tcb705_platform.py --ge-pl-dtbo ...`：封装比特流、HWH、寄存器表和 DTBO 哈希。
- `tcb705/ge_pl_contract.py`：加载前检查网口硬件描述、地址、时钟与复位连接。
- `scripts/start_ge_pl.py`：只在匹配平台自检通过后，初始化 GEM1 并挂载设备树。
- `tools/discover_ge_pl.py`：通过 ARP 探测及被动观察寻找控制器，不分配控制器 IP，不发送运动指令。

## 启动顺序

1. `so101-platform` 加载整套 FPGA，完成原七轴 AXI / IK / FK 自检并生成本次启动回执。
2. `tcb705-ge-pl` 验证平台、HWH 和 DTBO 哈希，检查物理 FCLK2 是否为 200 MHz。
3. 只修改 GEM1 自己的 RX/TX 时钟来源位，切到 EMIO；不能在运行中的 Linux 上执行整套 `ps7_init`，其中包含 CPU/DDR/PLL 初始化。
   必须保持 SLCR 解锁。资料盘 5.4 内核的 `arch/arm/mach-zynq/slcr.c` 在启动时解锁 SLCR，时钟驱动随后直接更新门控寄存器。用户态配置后再次锁定会导致内核认为 GEM1 时钟已开启，但 APER 寄存器实际没有改变，继而 MDIO 超时；还会影响软件重启。本次板上实测解除锁定后 MACB / PHY 探测立即成功，已修正并增加回归检查。
4. 独占 PHY 复位 GPIO，拉低 20 ms，拉高后等 200 ms，再附加设备树。
5. macb 创建第二网口，PHY 自动协商，桥接驱动按协商结果设置 FPGA 速率。
6. 启动原 GUI、显示与触摸。第二网口的地址只在发现控制器所在子网后确定，不能把历史 `192.168.4.4` 当作现场已确认地址。

设备树不提供 `tx_clk` 给 macb：网口 TX 速率由外部 FPGA 桥接器产生，GEM1 外部时钟选择由启动代码单独设置；GEM1 的 pclk/hclk 仍由 Linux 时钟驱动管理。

## 升级和恢复

先用 `stage_ge_pl.sh` 在新目录验证软件；`trial_ge_pl.sh` 只试加载，不替换开机版本。确认 FPGA 和网络正常后才用 `activate_ge_pl.sh` 安装启动服务。
旧版本和 systemd 配置备份保存在 `/home/xilinx/tcb705_deploy_backups/20261017_ge_pl_r1`。
当前 Linux 5.4 桥接驱动没有 remove 回调，因此网口已绑定后不热移除 MDIO 设备树、不再次全量重配 FPGA；改平台时应重启。加载器会阻止已绑定 GEM1 时重新下载整套 FPGA。

## 验证记录（持续更新）

- 官方 IP 示例仿真：通过。测试依次切换 1 Gb/s、100 Mb/s、10 Mb/s、回到 1 Gb/s，双向比较帧数据；日志出现 `Test completed successfully`。末尾 `Failure: Simulation stopped` 是示例 testbench 用于结束仿真的预期断言，不是数据错误。
- 整合后的复位拓扑仿真：通过，日志 `GE_PL_RESET_STARTUP_AND_RELOCK_PASS`。桥接 IP 的 `tx_reset` 同时复位内部 MMCM，因此外部复位控制器不能反过来等待同一个 MMCM 锁定，否则会永久互锁；本工程以稳定 PS FCLK2 为源，内部锁定由 IP 自己处理。
- 初版 ARM 软件回归：155 项通过。SLCR 修复后的 Windows 完整回归：156 项通过（无跳过）。修复版 ARM 回归待新包检查。
- 板端设备树编译：通过。
- 完整 FPGA 编译：通过，最终 setup slack +0.105 ns，hold slack +0.019 ns，DRC 错误 0；LUT 31,696，FF 36,499，DSP 146，BRAM 28。
- 板端新 FPGA 自检：3 个 IK 目标及 1,024 行完整七轴 FK 对比通过。
- 完整 MDIO 设备树：MACB 创建 eth1，YT8531 地址 4 绑定 Generic PHY，桥接地址 8 绑定 xgmiitorgmii；首次 `Couldn't find phydev` 是延迟探测，随后两个设备均成功绑定。
- 接到控制器后：曾协商到 100 Mb/s 全双工，并收到 `192.168.4.4 / f2:1e:7f:bf:19:87` 的 ARP 响应；随后链路下降。暂未取得 TCP 8001 连接或七轴坐标，不可将 ARP 发现当作 SDK 联调成功。
- 对断链进行自动协商重启、关闭休眠实验及单独 PHY 复位，暂未恢复；无效的休眠参数修改已恢复。待交换机对照试验，不能断定是驱动、网线或控制器问题。
- 修正 SLCR 后软件重启成功，原开机平台正常恢复。永久启动配置尚未替换。
