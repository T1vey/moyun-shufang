# 糖画坊：板端用户界面

## TCB705 本地线条图（2026-10-18）

主界面新增“已有线稿，直接画”：点击“选择本地线条图”，选择 PNG、JPG 或 WebP，查看原图后点击“生成绘画预览”。文件保存在打开浏览器的设备上即可；板上屏幕选择的是板上文件，电脑浏览器选择的是电脑文件。

本地线稿直接提取中心线，不调用云端生成；保留图片比例，使用 faithful 笔画模式。完成七轴规划后才显示“确认并开始绘制”，还需单独确认有人守在急停旁、周围无人。上传、提线和预览均不会启动机械臂。旧手机照片的云端生成流程继续可用。

支持静态图片，最大 20 MB、1600 万像素。建议深色线条、浅色背景。实机规划会读取控制器当前姿态，机械臂未连接时无法完成实机预览；模拟环境可独立验证整个流程。

控制界面仍仅接受本机请求和屏幕令牌。电脑使用公钥 SSH 本地转发后访问 `http://127.0.0.1:8095/`：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8095:127.0.0.1:8095 xilinx@192.168.2.99
```

新增 `/api/local-lineart` 沿用上传大小、完整解码、任务互斥和单次确认校验。相关测试见 `tests/test_user_gui_workflow.py`。

最终用户界面基于 `sugar_webui_20261011` 的焦糖、琥珀色样式，适配 MD0700R 1024×600 与 GT911。原始提供目录保留，集成版本位于本目录。

## 使用

1. 板子开机自动连接 **ESP8200**，密码 **12345678**。手机也连接这个网络；该网络需要能访问云端 API，并允许设备互访。
2. 用手机浏览器扫描板子右侧二维码，拍照或选择 JPG、PNG、WebP 静态图片，点击“上传并自动处理”。二维码自带本次会话配对信息，无需填写 API 密钥。
3. 板子自动调用现有云端配置生成线稿、提取并登记笔画，然后使用当前标定与 PL 加速规划真实轨迹。
4. 显示“准备完毕，可以开始工作”及静态预测图后，查看效果，在板子上点击“确认并开始绘制”。预测图来自规划保存的整数舵机指令，以与首页鱼形图案一致的金色糖丝、琥珀渐变和轻微高光显示，透明底融入深色画板，不显示笔画顺序、编号或动画。金色线宽为界面显示样式，不代表实物糖丝的粗细。
5. 绘制期间可以“停止绘画”。完成且归位确认后显示完成状态。手机无法直接启动运动，重启不会恢复上次的执行确认。

右上角“设置”打开原来的 SO101 调试控制台；其顶部“返回用户界面”回到糖画坊。任务处理中不能切换。调试控制台中的蓝牙收图、标定、网络和高级参数保留。进入设置时保持底层用户画面，避免启动调试窗口时露出黑色背景。

设置与调试现统一使用糖画坊主题：深棕背景、米色文字、金色主按钮与预测线、朱红停止按钮。绘画、四点标定、舵机调试、日志、Wi-Fi、蓝牙、图片库、屏幕键盘、文件选择和确认弹窗采用同一配色；PC 控制台与 Web 调试页同步。原始照片和云端线稿保持原始颜色。滚动页右侧“上 / 下 / 顶”可到达全部设置，顶部“停止”和“返回用户界面”始终可见。

主题实现为 `scripts/sugar_theme.py`、`scripts/sugar_dialogs.py`，配色对齐 `user_gui/static/base.css`；网页调试台为 `web/style.css`。文件选择保留格式过滤、目录导航、保存扩展名与覆盖确认；确认弹窗默认取消，关闭不等于同意。调试预测页保留可选的顺序/编号和参考路径，不影响主用户界面的纯预测图。

默认自动流程采用现有 seedream 云端配置、portrait 提示、100×100 mm、fine 笔画提取及唯一的 sugar_fast（糖画连续）运动模式。可使用通过多点/四点检查的新标定，或用户明确选择沿用的既有标定；当前板子按用户要求使用后者。兼容选择绑定原零位、TCP及纸面数据，不伪称新的精度验收已通过。两条路径都不可用时，上传会先提示检查标定。API 密钥继续从板子的私有配置文件读取，不在手机页面或发布包中提供。

2026-10-12 版默认启用 `sugar` 笔画整理：过滤小于 2 mm 的碎线，符合方向条件时合并至多 1 mm 的断口；保留全图小特征的兜底处理，不强制砍掉长笔画来凑笔数。后端参数 `--stroke-profile faithful` 可选择不整理的保真模式。原始云端线稿仍保存在图库。

完整计划先在内存就绪，历史文件在后台保存；保存期间断电可能使本次计划不进入历史。准备完毕仍需要屏幕点击确认，后台保存和手机上传都不会自动开画。归位高度保留 6 cm。每次上传的 `user_gui_jobs/<任务号>/timeline.json` 记录各阶段时间，`cloud_timing.json` 记录云端耗时和请求体积；界面显示云端、提线、规划用时。当前验收及未启用的后续优化见 `docs/PLANNING_SPEED.md`。

## 运行与依赖

板端入口：`scripts/run_user_gui.py`。`so101-md0700r` 显示服务启动它，服务端口为 8090；原有运动后端保持监听 127.0.0.1:8765。

板端系统 Python 需具备 WebKitGTK 和 GI（PYNQ Ubuntu 镜像）：

```sh
sudo apt-get install python3-gi gir1.2-webkit2-4.0
```

使用现有工程虚拟环境运行上传、云端及图像处理服务；沿用工程中的 Pillow、OpenCV、NumPy 等依赖。实际绘画还需现有标定有效、舵机串口可读、规划硬件就绪。单张上传不超过 20 MB / 1600 万像素。

界面切换不重启后端、不重新加载比特流。WebKit 窗口由系统 Python 运行；现有显示桥继续把 Xvfb 图像写入 LCD，GT911 服务继续负责触摸。

代码分工：

- `display_server.py`：二维码、手机上传、状态、仅本机允许的确认操作。
- `workflow.py`：云端→笔画→真实规划→预测→人工确认→执行状态机。
- `static/desktop.*`：板子界面；`static/mobile.*`：手机上传界面。
- `../scripts/run_user_gui.py`：保持上传服务与两个界面运行，管理切换。
- `../scripts/user_gui_kiosk.py`：本机 WebKit 显示窗口。

图片、预测图及云端结果保存到 `/home/xilinx/so101_data_work107` 下，不放入源代码目录。仅图像上传页对局域网开放；屏幕状态和运动确认接口只接受本机请求及独立屏幕令牌。配对码随服务启动更新。
