# TCB705 · ZYNQ7020 糖画坊

2026-10-17 更新：在独立天链工程中移植 1013 版的 CPU 批处理和 FPGA 调度方式，增加真正的七轴 HLS 核与融合 Vivado 工程。标定保留 ArmVision 的 A/B 两点范围、落笔 Z/UVW 和原抬笔参数。原 SO101 参考目录未修改。

**已实现可运行的七轴离线规划、原产品流程接入和模拟执行；尚未完成真实控制器透传运动。** 当前不是直接接上机械臂就能绘画的实机交付版。

**七轴加速版已编译并加载：** Vivado 2024.2 融合工程、bit/HWH/XSA 已生成，时序通过，DRC Error 为 0。板端真实 FPGA 的 3 个 IK 目标和 1024 组 FK 自检通过，重启后新平台、显示、触摸和天链标定自动恢复。CPU 批处理相对旧版约快 11～12 倍；当前 PL 尚未快于优化后的 CPU（8 笔人像片段分别约 15.72 s 和 10.72 s），不能把 CPU 提速当作 FPGA 收益。详细结果、重建命令和验收边界见 [FPGA 与 CPU 批量加速记录](docs/TCB705_FPGA与CPU批量加速_20261017.md)。此前仅 CPU 的部署保留在 [初次部署记录](docs/TCB705_板端部署记录_20261017.md)。

**同日新增网口联调准备：** 设备尚未到手，新增 SDK 只读坐标采集、TCP/基座/七轴映射比对、基座变换支持，以及独立的 SDK 关节目标发送适配库和故障注入测试。该发送库尚未接入真实绘画入口。具体边界和到货步骤见 [网口与坐标联调准备](docs/TCB705_网口与坐标联调准备_20261017.md)。

## 已经可以做什么

- 原糖画坊主界面、手机浏览器扫码传图、云端图像处理、中心线提取、预测图和用户确认流程。
- 官方 TCB705 URDF 的七轴 C++ 正解、Jacobian、连续逆解。ZYNQ ARM 完成轨迹组织、重定时和独立校验；有有效启动凭据时通过七轴 PL 核求解连续 IK 候选批次，否则使用原生 CPU 批次。不调用控制器 IK，也不使用旧五轴 PL 核。
- 复用 1013 的 DDR 批传、物理 IP 独占、启动凭据、取消与 DMA 排空机制，增加七轴专用 ABI、模型、时钟和复位检查。FPGA 每批最多 64 个 IK 目标，FK 检验批次最多 1024 行。
- 上一点关节解作为下一点初值和参考，限位、限步长、回溯与路径细分；失败会报告所在笔画与阶段。
- 七轴协调的固定工具姿态抬落笔：世界 XY 保持，Z 使用标定高度。ArmVision 配置为笔间 **8 mm**、最后一笔 **60 mm**（均相对纸面）；独立算法示例仍为 30 mm。
- C2 五次关节轨迹、速度/加速度/jerk 重定时、尖角局部起停；没有每画一笔固定等待若干秒的逻辑。
- 经过 SDK float32 角度转换再做 FK 检验，由最终关节目标生成金色预测图。
- 冻结配置和模型摘要、二进制轨迹 SHA256/CRC32 校验、模拟进程执行；配置变化后旧计划不能执行。
- 华成 V2.4.1 ARM32 SDK 的 C++ **只读连接与七轴反馈适配源码**；ArmVision 原 Web 世界坐标读取协议和 A/B、落笔点采集页面。

## 在这台 Windows 电脑上运行

双击根目录 `run_tcb705.bat`，默认加载 `robots/tcb705/profile.armvision.json`；点“设置”查看或编辑与 ArmVision 一致的标定字段。现用原软件数值已导入，模型/TCP/坐标映射未确认前不会生成假定正确的真实位置规划。

独立算法演示使用 `run_tcb705_demo.bat`，显式加载 `profile.demo.json` 并使用独立数据目录，避免示例坐标覆盖实际标定。本地 `.venv` 和 Windows 数值核心已准备好。两个入口均不驱动机械臂。

默认主界面：`http://127.0.0.1:8095/`；后端仅监听 `127.0.0.1:8785`。

在独立算法演示中进入“设置”，选择方形/圆形/双笔画，点“生成预测图”→“模拟执行”。手机可用二维码上传，但云端生成仍需原 API 密钥及外网。离线预设图形不调用云端、不产生 API 费用。

命令行复现：

```powershell
.\.venv\Scripts\python.exe scripts/tcb705_demo.py --shape square
.\.venv\Scripts\python.exe scripts/run_tcb705.py --simulation
.\.venv\Scripts\python.exe scripts/run_tcb705.py --simulation --profile robots/tcb705/profile.demo.json --data-dir build/tcb705/demo_ui
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_tcb705.py -v
```

在另一台电脑重新构建时安装 `requirements-tcb705.txt`，用 C++ 编译器运行 `python scripts/build_tcb705.py --cxx <g++路径>`。本机编译器位于 `D:/Xilinx/Vitis_HLS/2020.2/tps/win64/msys64/mingw64/bin/g++.exe`。Windows 二进制不能复制到 ARM 上直接使用。

## ZYNQ 板端准备

1. 将源码复制到 `/home/xilinx/ZYNQArm`，不复制 Windows `.venv` 和 `build/`。
2. 使用现有 PYNQ 兼容的 Python 环境，确认可导入 `numpy`、`PIL`、`cv2`；原图形客户端还需要 `tkinter`，当前图像链路不要求在 ARM 上重装整个历史 requirements 文件。
3. 在项目目录执行 `sh deploy/tcb705/build_on_zynq.sh`：原生编译核心、模拟器和 SDK 只读工具，运行离线测试。需要 ARM32 g++（SDK 头文件要求 C++17）及开发环境。
4. 离线演示用 `--simulation --profile robots/tcb705/profile.demo.json`，数据目录与实际参数分开。当前板端已安装 `tcb705-ui.service`，使用原 ArmVision 参数及 `--allow-real` 只读模式，不使用模拟参数冒充真实标定。
5. 完整 FPGA 部署使用 `deploy/tcb705/stage_fpga_release.sh` → `activate_fpga_release.sh` → `verify_fpga_release.sh`，先核对源码并原生编译，再排空 DMA、加载配套平台、实测 IK/FK，最后恢复界面。`so101-platform` 在每次 Linux 启动后加载七轴/LCD/GT911 融合比特流，应用只附加到已经自检通过的平台。

板端已连接 ESP8200，当前 Wi-Fi 地址为 `10.217.38.90`，上传端口为 `8095`，手机使用屏幕上的二维码。电脑部署链路为 `192.168.2.99`；控制器 IP 仍待实际配置。连接 ESP8200 的配置已启用自动连接，未修改电脑网络。

## 实机仍需完成

七轴映射、TCP/纸面、动态限制、碰撞环境和起始姿态需用本机数据核对。控制器的透传周期、缓冲/断流及停止语义、反馈与发送线程约定要完成联调，之后才能实现并验证真实 `PluseToServo` 执行状态机。当前执行器明确拒绝真实运动，改配置布尔值不能绕过。

电脑与板端软件回归各通过 151 项，包含时钟、复位和会话复用检查；每次开机加载另行执行独立硬件自检。尚未完成真实控制器通信和实机绘画验收。示例速度、4 ms 周期和示例标定不代表机器的正式参数；模型几何误差也不等于实际纸面精度。
