书法模式：预设基本笔画与偏旁
工程：ZYNQArm
日期：2026-10-21

本次范围
在当前主用户 GUI 中加入“书法模式 / 笔画工坊”。
实现预设模块选择、尺寸选择、提按示意、轨迹规划和既有 SDK 执行流程。
暂不做任意汉字自动拼装、自动笔画识别、侧锋转笔或力传感闭环。
当前修改位于电脑工程目录，未自动更新板子，也没有驱动实物试写。

已知毛笔条件
墨管供墨；笔毛长 9 mm，最粗直径 2 mm。
这是外形尺寸，不是落纸线宽或允许下压量。
没有实测数据时最大下压量为 0、标定状态为未核对；软件不会自动填入 5 mm。

如何使用
1. 主界面右上角进入“书法模式”。
2. 切换“基本笔画”或“偏旁部首”，点选模块。
3. 选择模块大小（20、30、40、50、60 mm 的名义 50 单位字框比例）。
   XY 等比例缩放，放在已标定纸面的中心，下压量不会跟着字号同比放大。
4. “仅规划预览”只准备计划；之后可从主界面确认执行。
5. “书写所选”代表本次执行请求，规划成功后通过主界面原有流程自动执行。
   该按钮不会直接绕过规划、标定、起始姿态和下发轨迹校验。
6. 主界面可取消规划、停止书写，完成后选择下一个模块。
   计划失败不会自动重试运动，刷新页面不会自行恢复一次自动书写请求。

首次实际书写
先在原天链设置界面完成当前毛笔工具 TCP 与纸面零点核对。
随后展开“毛笔标定参数”，填写这支笔实际验证过的下压上限、书法基准速度，
勾选已经核对并保存。
首版允许输入的下压上限范围为 0.01～1.50 mm，基准速度为 1～30%。
上述范围是首版软件限制，不是对实际毛笔承压能力的保证。
工具、纸面、姿态或运动学配置变化后，毛笔核对状态失效，需重新核对保存。
实际墨迹还受供墨、墨水、纸张与笔毛回弹影响；图中粗细只是提按示意。

模块清单
基本笔画 15 个：
横、垂露竖、悬针竖、点、长撇、短撇、捺、提、竖钩、横钩、
横折、竖折、撇折、卧钩、横折提。

偏旁 10 个：
口、氵、亻、木、日、土、女、山、心、讠。

每个模块已经包含起笔、行笔、收笔的 XY、下压比例和速度比例。
复合笔画（横折等）在同一笔内连接；偏旁内部的各笔之间会抬笔。
按实际笔顺修正参考文档中的部分示例：
土＝横、竖、横；女＝撇折、撇、横；氵＝点、点、提。
这是用于调试的手工参数化写法，不是已经过书法实物验收的字帖字体。
初版固定竖直笔轴，以提按与变速模拟轻重，不把它称为以牛顿为单位的发力控制。
连续供墨不加固定长时间顿笔，先以减速和深度变化表达顿笔，避免未经测试的积墨。

编辑预设的位置
calligraphy/presets.py
  STROKES：基本笔画关键帧，每点为 [x, y, depth_ratio, feed_ratio]。
  坐标基于 50 单位字框，X 向右、Y 向下。
  depth_ratio 0 表示自然笔尖接触纸面的参考位置，不表示已经离纸。
  真正离纸由规划器的 LIFT 阶段完成。
  feed_ratio 乘以书法基准速度传给现有 SDK，不能当作毫米/秒。
  RADICALS：按笔顺引用基本笔画，并指定位置和缩放范围。
  只允许有限范围的服务器预设任务；前端不会直接传任意机器人关节命令。
  修改模块时应更新 VERSION，旧书法计划会被拒绝。

calligraphy/execution.py
  检查实际关节直线插补的笔轴姿态、下压上限与纸面范围。
  首版要求水平纸面，竖直笔轴由七轴协同实现。

实际接入改动
• tcb705/planner.py：固定笔顺和方向、三维提按、分段速度；DRAW 最大采样间距 0.4 mm。
• tcb705/artifact.py：冻结/保存/加载保留书法参数和速度，内存节点增加书法摘要。
• tcb705/web_executor.py：书法模式保留所有提按节点，检查下发轨迹；不在落笔中任意切块。
• tcb705/sdk_motion.py：将书法程序块的 speed 传给已有 specifyGlobalSpeed 比例通道。
• tcb705/workbench.py、app.py：模块目录、毛笔参数、书法任务接口。
• user_gui/workflow.py、display_server.py：接通本地模块→规划→执行，复用任务互斥和屏幕鉴权。
• user_gui/static/calligraphy.*、desktop.*：同风格模块选择界面。

为什么没有直接使用文档示例的 250 Hz servo_movel
该示例不能仅凭函数名称就证明和当前控制器、SDK、返回值及节拍约定匹配。
本版采用工程已有的本地七轴 IK + 关节 SDK 下发通道，逐段比例通过现有桥接传递。
不声称已实现 250 Hz 末端伺服流或力控。

当前性能策略与限制
预设任务较小，优先保留全部提按/变速节点，绕过原 C++ 和 Python 节点合并。
原 C++ ABI、动态库和 PL 位流没有变化，因此本次不需要重编 Vivado。
本地 IK 继续走项目已有 PL/CPU 批处理分派；电脑模拟测试使用 CPU 原生库。
为使下压和笔轴检查对应已知关节插补，书法接触段暂不启用未经毛笔实测的控制器圆滑过渡。
这可能比完成调参后的版本慢；不能把本次模块功能称作最快书写版。
之后应通过实机短线试验验证队列深度、过渡参数和墨迹，才开放更积极的融合与提速。

与原绘画流程的区别
原图片绘画行为保持原路径。
书法模式不允许用归位模式的“只告警继续”忽略越界、异常低位或停滞。
书法异常后停止，不盲目执行原有的异常自动归位。
支持原控制器程序与 SDK 程序块格式，但实物书法必须使用本地 IK 的 joint 模式。
没有电控供墨接口时，点击停止只能停止运动，不能保证墨管停止出墨。
