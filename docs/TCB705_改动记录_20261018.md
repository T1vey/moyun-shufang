## 2. 云端提示词（`cloud.py`）

- 版本 `plotter-sparse-v4`。最终 = **通用部分**（简略或细节）+ **主题部分**；“自己写”= 通用部分 + 用户描述（≤200 字，去控制字符）+ “与线条要求冲突时以线条要求为准”。
- 简略通用部分：约 15～25 笔（保持原笔画数），另加“不要阴影、排线、纹理、上色和文字”“宁可省略也不要零碎短线”。
- 细节通用部分（新）：不刻意压笔画但一般不超过约 60 笔；单线、不填色、线间距 ≥12 像素、不要细小闭环和碎点——这些是本系统能画出来的条件。
- 主题：人物（简略=原极简分配；**细节=新写的头部到上半身版本**）、物体（内部结构线最多 2～4 条）、山水（新，不含人物、动物、建筑）。
- 云端拒绝时显示**错误码**（如 `InputImageSensitiveContentDetected`、`InvalidParameter`）和中文提示；仍不记录原始说明、账号、网址。每个手机任务写 `cloud_request.json`（主题、模式、提示词长度）。
- 备份：`portrait_detail_backup_20261018/`、`cloud_errors_backup_20261018/`。

## 3. 规划

| 改动 | 结果 | 板上备份 |
|---|---|---|
| 演示配置细分 1 mm → 0.5 mm（与实机一致） | 图库中大部分线稿可规划 | 见 `planner_native_backup_20261018/` |
| 帧数上限 15 万 → **80 万**（约 53 分钟轨迹，规划峰值约 0.53 KB/帧） | 复杂人像不再因 `FRAME_BUDGET` 失败 | `frame_cap_backup_20261018/` |
| **FPGA 真正用上**：GUI 规划在后台线程里缺 asyncio 事件循环，PYNQ 打不开 FPGA、退回 CPU；现在线程共用一个循环 | 板上规划 `ik_backend = ZYNQ_PL_7R_BATCH`，5266 行 CPU 复核 0 拒绝 | `pl_event_loop_backup_20261018/` |
| **规划提速**：碰撞检查、4 ms 帧采样与 float32 取整搬到 C++，批处理用两个 A9 核；预测图生成去掉重复计算 | 人像 23.6 s → 12.5 s，鸭子 10.2 s → 5.5 s，**全部输出逐字节一致**（板上新旧代码对比） | `planner_native_backup_20261018/`（含旧 `libtcb_core.so`） |
| **实机计划不写文件**：规划结果留在内存交给执行，仍核对配置指纹与模型哈希；模拟模式照常保存 | 少写约 10 MB/次到 SD 卡 | `onetap_memory_backup_20261018/` |

仍未解决：个别复杂线稿 `CURVE_GEOMETRY`（某段偏差 0.1001～0.106 mm，超 0.1 mm 限）；根治需要规划器只在失败区间自适应细分。

## 4. 执行（`tcb705/web_executor.py`、`workbench.py`）
